# P2 · Monaco editor

P2 replaces the problem-page editor with locally bundled Monaco 0.58.0. The installed Windows Chrome loaded the unpacked extension with its existing ID, `mabfdombglhmfnjklbnoglebinejifdi`. Code edited in Monaco compiled with the registered MSVC host and passed both fixture samples. A separate anonymous read of the public A+B statement also passed its sample locally. The starting revision was `cdd31ab`.

The three project documents now make the owner's BOJ account-safety rules mandatory at every phase gate. The regression harness opens a local prefill fixture using the existing shortcut, verifies the final button stays untouched and drives subsequent judge states with fixture data. ## Editor and privilege boundary

- The problem content script owns the workspace and lazily opens an extension-origin iframe inside a closed shadow root. Only the frame HTML is web-accessible, scoped to the two existing HTTPS BOJ origins. The packaged scripts, worker and font load inside that frame. Manifest version, extension key, existing permissions and the default extension CSP are preserved. [Manifest](../../manifest.json) · [Chrome extension CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy)
- The frame obtains its tab ID from a narrowly scoped extension message, then uses an internal Chrome port to the top content script. The content script checks the extension ID, exact frame URL and per-instance nonce. There is no page-window message listener for editor operations. A trusted editor keystroke or workspace control initiates execution. The existing content script and background worker own the native job and remote consent flow. [Problem-side adapter](../../content/editor.js) · [Frame protocol](../../editor/frame.js) · [Background](../../background.js)
- The Monaco adapter owns model creation, configuration, text edits, selection, focus, scroll and disposal. A stable virtual URI identifies each problem and language. UTF-16 offsets and generation-tagged updates keep queued edits attached to the right document. C, C++ and Python have local tokenizers and keyword completion. The packaged worker supplies words from the current document. This phase adds the editor seam for a future language provider. [Monaco adapter](../../editor/monaco-adapter.js) · [Local build inputs](../../tools/monaco/entry.mjs)
- Existing `draft:<problem>:cpp|c|py` records keep their zero-based `{line,ch}` cursor and optional scroll offsets. Opening and saving an unedited mixed-line-ending, BOM-prefixed draft preserved its exact string. The editor flushes before switching language, running or prefilling. The frame captures its final model on navigation. Immediate edit/reload, subsequent Back navigation, tab isolation and collapse/reopen undo were checked. Collapse disposes the view and model and the worker exits. The loaded frame and Monaco's bounded undo state stay available for a fast reopen. [Worker and loaded resources](evidence/p2/worker.json) · [Back navigation](evidence/p2/history.json)
- The release allowlist includes the new frame and local assets. CodeMirror 5 remains in the offline submission fixture to represent the site's editor. Its license accompanies the fixture. The Monaco build pins esbuild 0.28.2 and records dependency integrity. A clean lockfile install reproduced all eleven vendor files byte for byte, including the notices. [Build](../../tools/monaco/build.mjs) · [Asset sizes and SHA-256](evidence/p2/monaco-build.json) · [Packaging](../../.github/workflows/release.yml)

## Startup and resource use

Each phase ran in three fresh Chrome 158.0.8127.37 profiles, at 1280 × 800, opening the same 400-line saved C++ draft twice per tab. Times include the real button click through the first visible, focused editor. An offline capability response isolates editor startup from native compiler discovery. Heap values are CDP used JavaScript heap, summed across the page and its extension frame. They exclude the Chrome process working set and use ordinary garbage collection. [Measurement harness](../../tests/p0/editor-performance.mjs) · [All observations](evidence/p2/performance.json)

| Median | P1 CodeMirror | P2 Monaco |
| --- | ---: | ---: |
| Before opening, page heap | 2.6 MiB | 2.1 MiB |
| First open | 223 ms | 367 ms |
| Reopen in the same tab | 73 ms | 71 ms |
| Heap after first open | 3.2 MiB | 13.5 MiB |

The packaged vendor directory grew from 490,081 to 4,039,485 bytes including notices. The median first open took 144 ms longer. All three P2 profiles reported zero editor views, models and workers after collapse. The dedicated completion test also observed the packaged worker doing work and disappearing on collapse, with zero CSP or worker fallback errors. These six short trials measure this machine and draft.

## Reproduce

From the repository root, use installed Chrome, Node/npm, Python and the P1 registered Windows host. The extension runs directly from the checked-in vendor files. Rebuilding them requires the pinned developer dependencies.

```powershell
npm.cmd ci --prefix tools/monaco --ignore-scripts --no-audit --no-fund
npm.cmd --prefix tools/monaco run build
npm.cmd ci --prefix tests/p0 --ignore-scripts --no-audit --no-fund
npm.cmd --prefix tests/p0 test
npm.cmd --prefix tests/p0 run test:p1
npm.cmd --prefix tests/p0 run test:p2
python -B tests/p0/native_test.py
python -B tests/p0/native_p1_test.py
node tests/p0/windows-ime.mjs
node tests/p0/editor-performance.mjs p2
```

The IME test requires the installed Korean layout and a foreground-capable Windows desktop. It targets its own disposable Chrome window, checks foreground ownership before every chord and restores any Hangul-mode toggle it made. Set `CBOJ_TEST_PYTHON` if Python is outside PATH. For the P1 timing comparison, extract the release inputs from `git archive cdd31ab` to a separate directory and pass its path after `p1` to the measurement script. The optional `node tests/p0/live-smoke.mjs --msvc` reads the public statement and compiles only locally. Routine regressions run offline.

## Limits at the review gate

- The singleton `cbojSubmitTab` still closes the first pending submission tab when a second problem opens its own. The first problem retains its pending prompt. The fixture preserves this expected failure for the submission-lifecycle phase. [P0 finding](P0.md) · [P1 follow-up](P1.md)
- Authenticated BOJ submission and the owner's external Git integration can be verified only through normal, owner-initiated problem-solving on the official submission page. Their production behavior remains unverified. Wandbox request formation, fallback consent and presentation used doubles. The tests sent no source to BOJ or Wandbox.
- Browser Back restored the latest edit and one working model. Chrome performed a fresh history navigation in the measured fixture, so a retained back/forward-cache document remains unverified. Service-worker suspension during an active native job also remains open from P1. The IME checks cover the installed Windows layout and Chrome version. Older browsers that require a textarea fallback remain unverified. The find widget's expand control also opens replace when a browser reserves Ctrl+H.
- The original extension's redistribution rights remain unresolved. The new dependency notices cover their named components. The gate ends at local review.
