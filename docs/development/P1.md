## Implementation and compatibility

- **MSVC discovery.** The host queries `vswhere` for installations with x64 C++ tools, including Build Tools, and checks standard edition directories as a fallback. A child process runs `VsDevCmd.bat` for x64 host and target. Discovery requires a successful standard-library compile, link and execution before advertising MSVC. The build uses `/O2 /EHsc /utf-8 /Zc:__cplusplus` and the selected `/std:c++17` or `/std:c++20`. The developer environment exists only in child processes. [Toolchain implementation](../../host/toolchains.py) · [Microsoft command-line environment](https://learn.microsoft.com/en-us/cpp/build/building-on-the-command-line?view=msvc-170)
- **Selection and saved work.** The popup stores the runner choice on this machine. Automatic mode prefers MSVC for C++17/20 and uses an available G++ for other C++ standards. C uses GCC and Python uses the installed interpreter. A fresh MSVC C++ template starts with `<iostream>` and keeps fast I/O and `$0` cursor placement. Existing drafts and custom templates take priority. Unversioned native requests retain their GNU defaults. The old host continues to serve compatible languages and shows an installer repair hint for MSVC.
- **Remote execution.** Explicit Wandbox selection discloses that it sends the source and inputs. When a local runner is unavailable, a per-run prompt offers that choice. Dismissing it produced zero remote compile calls. The worker validates the problem-page sender and request before forwarding local jobs or a confirmed remote run. The manifest retains the existing extension identity, CSP and permissions.
- **Build reuse.** Each native connection owns an in-memory LRU cache of up to eight executables, 32 MiB total and 8 MiB per entry. Identity includes source, language, mode, compiler path/version and binary stamps, arguments and effective environment. Before a hit the host checks recorded header sizes and modification times. Failed builds produce diagnostics and never enter the cache. Each sample gets a fresh process and working directory. Disconnect releases the cache.
- **Cleanup.** The Windows launcher waits until it belongs to a kill-on-close Job Object before starting the compiler or program. Normal completion, cancellation, timeout and disconnect close the job and join pipe readers. The host completes workspace cleanup before reporting a terminal result. An abruptly killed host can leave files until the next connection. Startup reclaims only marked runner directories whose owner PID has exited. The forced-exit test observed both child PIDs terminate, verified subsequent reclamation and preserved an unrelated lookalike directory. [Process ownership](../../host/process_tree.py) · [Workspace recovery](../../host/workspace.py) · [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)

## Reproduction and manual checks

From the repository root on this Windows machine, use the existing toolchains and installed Chrome. The browser suites create disposable profiles. The P0 and P1 offline suites use local pages. The last command opens the public problem with read-only web requests and runs the sample locally.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File host/install.ps1 -RegisterOnly -ChromeOnly
npm.cmd ci --prefix tests/p0 --ignore-scripts --no-audit --no-fund
node tests/p0/registration-check.mjs installed
npm.cmd --prefix tests/p0 test
npm.cmd --prefix tests/p0 run test:p1
$runnerPython = Join-Path $env:LOCALAPPDATA 'Programs\Python\Python314\python.exe'
& $runnerPython -B tests/p0/native_test.py
& $runnerPython -B tests/p0/native_p1_test.py
node tests/p0/live-smoke.mjs --msvc
```

To repeat the uninstall check, run `host/uninstall.ps1 -ChromeOnly -Yes`, then `node tests/p0/registration-check.mjs missing`. The install and installed-check commands above restore the runner. For a manual run, open a problem with the unpacked extension, choose automatic execution, and run its samples twice. The terminal displays a fresh compile and then cache reuse. A program that flushes output after reading a line lets you check Enter, Ctrl+D and Ctrl+C in the terminal.

## Known defect and remaining limits

- **Concurrent submission tabs still fail isolation.** Opening a submission from a second problem closes the first submission tab, while its original problem still displays a pending prompt. The singleton `cbojSubmitTab` and its expected-failure assertion remain available for a later submission-lifecycle change. Independent native execution in two tabs passed. [P0 finding](P0.md) · [Recorded failure](evidence/p1/browser-results.json)
- Wandbox request formation and consent were tested with service doubles. Authenticated BOJ judging and the owner’s external submission-to-Git integration require an owner-assisted submission. The fixture verified manual prefill, focus, status and cleanup. Windows OS-level IME composition and service-worker suspension during a job remain unverified.
- The Windows Job Object controls process lifetime. Local source executes with the current user’s permissions. MSVC and BOJ’s GNU toolchain can differ on extensions and timings. A fresh connection repeats discovery and starts with an empty cache.
- P1 has no outstanding verification blocker on this machine. The upstream redistribution-license question recorded in P0 remains a release blocker. The phase stops at local review.
