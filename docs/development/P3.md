## From the editor to clangd

- Opening a C++ model starts a dedicated analysis session. The Monaco frame sends fixed operations through the existing nonce-bound extension port to its top-frame content script. The service worker checks the sender, BOJ problem URL, operation, fields, source size and coordinates before contacting the native host. Only the registered extension origin can launch the host. The worker waits for the source-free capability probe before forwarding a draft. No new permissions, web-accessible resources, page message listeners, executable downloads or CSP exceptions were needed. [Frame adapter](../../editor/cpp-analysis.js) · [Content bridge](../../content/editor.js) · [Service worker bridge](../../shared/analysis-port.js)
- Each connection owns one local clangd process, one private temporary compilation database and one virtual main file. The empty file establishes identity. The draft travels in memory over native messaging and then LSP over standard I/O. The only analysis operations exposed to the editor are full document synchronization, completion, signature help, hover, definition and cancellation. The host chooses every path, compiler argument and LSP method. User and project clangd configuration and background disk indexing are disabled for this standalone workspace. [Session](../../host/clangd_session.py) · [LSP specification](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)
- Discovery checks installed executables, Visual Studio installations, LLVM and IDE bundle locations. It constructs a per-file compile command with the C++ standard and judge macros. The Windows MSVC profile specifies the x64 Windows target, compiler compatibility version and actual SDK/STL include roots. GCC supplies its target triple and C++ include search list. A fixed vector/string program must pass the candidate server's own parse check before the host uses the pairing. The language server binary and toolchain headers remain on the owner's machine. [Discovery](../../host/clangd_tools.py) · [clangd compile commands](https://clangd.llvm.org/design/compile-commands)
- Standard C++14 and newer drafts prefer MSVC headers here. An explicit `bits/` or `ext/pb_ds/` include requests GCC headers first, including for the GNU starter template. An edit that changes this preference reopens analysis against the current draft. The execution selection has no role in discovery. Users see the analysis profile under the editor and the execution backend in the existing results toolbar. MSVC and clangd can diagnose the same code differently.
- The host negotiates UTF-16, sends a complete initial document, and waits for clangd's first AST before advertising semantic completion. Edits coalesce for 110 ms and flush before a request. Full replacements preserve Unicode and line breaks without replaying ranges against the wrong revision. Versions, request IDs, document generations and session identities reject superseded output. Edits cancel pending requests and clear old markers. A cancellation token also sends LSP cancellation when a widget closes. [Monaco providers](../../editor/cpp-analysis.js) · [Native wire tests](../../tests/p0/native_p3_test.py)
- F12 moves to declarations within the draft. For an installed header it opens a read-only, line-numbered excerpt. Only server-resolved declarations inside the discovered header roots qualify. The editor receives a basename and bounded text. Escape returns to the draft. Hover content renders as plain text, and diagnostic markers identify clangd as their source.
- C, Python and collapsed editors own no language server. Closing a C++ document requests ordered shutdown and releases its providers and markers. A Windows kill-on-close Job Object covers the server and its launcher. The next host reclaims a marked temporary directory after abrupt owner termination. Unexpected loss permits up to two automatic restarts with the current model. Missing hosts, incompatible hosts, missing clangd, unsupported headers and drafts above 512 KiB leave basic editing and completion available.

## Reproduction

Use the existing Windows C++ toolchains and a locally installed clangd. The status line identifies missing prerequisites. If clangd is absent, an owner who wants semantic analysis can install an LLVM distribution and reopen the editor. Detection also checks the standard LLVM installation directory. An older project host can be refreshed with `host/install.ps1 -RegisterOnly -ChromeOnly`. This mode uses the existing Python and compilers. [clangd installation guide](https://clangd.llvm.org/installation)

```powershell
npm.cmd --prefix tools/monaco run build
python -B tests/p0/native_test.py
python -B tests/p0/native_p1_test.py
python -B tests/p0/native_p3_test.py
npm.cmd --prefix tests/p0 test
npm.cmd --prefix tests/p0 run test:p1
npm.cmd --prefix tests/p0 run test:p2
npm.cmd --prefix tests/p0 run test:p3
node tests/p0/editor-performance.mjs p3
node tests/p0/windows-ime.mjs
```

For manual review, open a fixture problem, select Wandbox, and enter a vector of strings. Type a dot after the vector, select `push_back`, and use signature help inside a two-argument function call. F12 on a local function and an STL method exercises both navigation paths. Change a member name to an unknown name after Korean text and an emoji, then correct it. Closing the panel releases its analysis processes. All submission, polling and judging checks use the offline fixtures.

## Limits carried to review

- The existing single submission-tab slot still closes the first pending submission form when a second problem opens its form. The original problem retains its pending prompt. The local regression continues to expect this failure. [P0 finding](P0.md) · [P1 follow-up](P1.md)
- Authenticated production submission and the owner's external submission-to-Git integration remain owner-initiated checks. Wandbox request and consent regressions used service doubles. The P3 analysis tests selected Wandbox in the real editor without executing a remote program. No BOJ or Wandbox submission was made.
- Verification covered the installed Windows x64 Chrome, clangd and header versions listed above. Other server builds, operating systems, forced service-worker suspension during a native job, retained back/forward-cache documents and older textarea-based IME implementations remain unverified. [P2 limitations](P2.md)
- The workspace represents one draft per tab. Header navigation shows a bounded excerpt. Each reopened editor starts its own language server, and active C++ tabs each incur its memory cost. A fresh problem using the automatic stock C++ template still waits for P1's compiler probe to choose the template. Saved drafts and explicit Wandbox selection can open directly.
- The upstream extension's redistribution license remains unresolved. P3 reuses the pinned Monaco build and existing notices and ships no clangd binary or compiler headers. The phase stops at local review. [P0 license inventory](P0.md)
