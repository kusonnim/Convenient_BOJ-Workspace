## Upstream inventory

| Area | Workspace behavior and compatibility |
| --- | --- |
| Java editing and data | The upstream Java template opens as `Main.java` in Monaco with syntax coloring, keywords, common library names, document words and user snippets. Templates keep the `$0` cursor marker. Java uses the existing `draft:<problem>:java` and `templates.java` keys. Loading an existing draft preserves its line endings and UTF-16 cursor. An updated BOJ language list keeps an active buffer associated with its original family. |
| Local Java | The helper discovers a matching `javac` and `java`, supports the upstream 512 MiB Java thread stack and judge properties, and compiles numbered BOJ Java choices with the requested release. An unavailable release produces the compiler's diagnostic. Compiled classes share the bounded local build cache. Each input starts a fresh JVM. Interactive input, EOF, stop, deadlines and process-tree cleanup use the existing runner. Updating the helper enables these additive capabilities under runner protocol 2. |
| Online Java | Explicit Wandbox selection or the per-run confirmation authorizes sending source and input. The service worker discovers an OpenJDK compiler. It sends the user's unchanged source as named `Main.java` alongside the provider's required `prog.java` stub, so a public `Main` compiles with the original line numbers. The fixture captured the actual payload and replayed its compiler arguments with the installed JDK. The hosted compiler list was checked with a read-only GET. [Wandbox compiler definition](https://github.com/melpon/wandbox-builder/blob/master/cattleshed-conf/compilers.py) · [Java launcher](https://github.com/melpon/wandbox-builder/blob/master/ga-build/openjdk/resources/run-java.sh.in) |
| Stopwatch | The toolbar starts, pauses and resets the upstream `timer:<problem>` record. Auto-start defaults to off. Tabs showing the same problem share the elapsed time. The worker freezes the duration when the owning submission receives an accepted result and includes it in the judge card. A collapsed or hidden panel stops repainting. Backups include the timer, Java drafts, templates and snippets. |
| Windows stack reserve | The original GCC reserve of 256 MiB is the default. The popup accepts 1–512 MiB. GCC uses `-Wl,--stack,<bytes>` for C and C++, and MSVC uses `/link /STACK:<bytes>` for C++. A reserve change invalidates the executable cache. A helper without the capability keeps its existing arguments. The MSVC/GCC choice continues to select the C++ toolchain independently of Java. |
| Wandbox retries and batches | Up to three attempts on a network failure or HTTP 429, 500, 502, 503 or 504. The normal retry delays are 800 and 1,600 ms. Each request has a 40-second deadline. A server-requested wait of up to 10 seconds extends the normal delay when needed. Longer `Retry-After` values return an error and leave the next attempt to the user. One service-worker limit covers concurrent tabs and keeps at most three compiles in flight. Window navigation, stop and tab closure cancel queued/running jobs. Input order and separate output streams survive a retry. |
| BOJ form and results | Problem/sample and status readers retain the upstream selector definitions and P4's tab ownership. Both form execution worlds now use the same fixed selectors. The MAIN world has its own packaged URL. Language resolution prefers an exact ID and display name, with an unambiguous name fallback. The owner can inspect and change the prefilled language, code and visibility before personally submitting on BOJ. |
| Features already integrated | P4 and P4.1 retained custom test records, normalized comparisons, sample identification, C/C++ switch-label indentation, editor navigation and workspace data backups. Monaco remains the editing engine. C++ retains local clangd and C/C++ retain explicit local formatting. The upstream automatic-completion toggle controls Monaco suggestions. Ctrl+Space remains available in every supported language. The official BOJ form continues to use BOJ's own editor. |

## Remaining differences from upstream and BOJ

Java has Monaco language, snippet and document-word completion. Semantic C++ IntelliSense uses clangd, and the formatter supports C and C++. The native interactive terminal streams input while the program runs. Wandbox receives the complete input for each case and returns the result when the job finishes. The selected Java compiler and BOJ's production JVM can differ in version or resource limits. Checked release targets are recorded below. BOJ's official form owns the final language choice and submission.

The archived upstream v1.4.0 helper still completed a Java batch over its original wire protocol. That helper uses its installed JDK's default compilation target. Helper 2.1 applies the BOJ release, the configured C/C++ reserve and the newer cleanup guarantees.

### Corrections and reruns

- The Windows JDK wrote redirected output in the console code page. Setting the compiler and JVM stream encodings explicitly preserved Korean and emoji on both output streams while retaining compiler diagnostics. JDK 27 and an independently selected JetBrains JDK 21.0.10 passed Java batch and interactive checks. Java 11 and 17 are compilation targets in these checks. Other JDK distributions and physical JDK 8 were not exercised.
- Using a single content-script URL for both form worlds left the isolated script without its selector table in Chrome. A generated copy gives the MAIN world its own URL. The table is byte-identical after line-ending normalization. The form regression then verified language selection, code prefilling and two outstanding submissions against local fixtures.
- A cold switch from upstream v1.4.0 exposed the new manifest while Chrome was still running upstream's cached service worker. The language selector appeared, but the worker lacked the editor connection route. A distinct worker entry URL made the first open after replacement load the workspace editor. The same upstream profile then restored its Java draft and clock. The historical fork profiles also retained their saved settings through upgrade and restart. The package smoke test identifies the editor by its extension frame URL because the iframe lives inside a closed shadow root. [Upgrade observations](evidence/p5/upgrades.json)
- An initial ZIP comparison under different Git configurations produced different text bytes. The packager now pins checkout conversion for its archive operation and respects tracked CRLF attributes on Windows scripts. Both final SHA-256 values matched with Windows-style and CI-style Git settings.
- An early native run could not discover the GCC headers once. The isolated repeat and the complete native runs passed with the installed GCC headers, including the final 35-test run. The explicit pause interrupted a separate Chrome run. Verification subsequently removed its one abandoned private registry alias after checking the owner process and manifest. The final registry check found zero private test aliases for this checkout. The production registration still answered as helper 2.0.0. The isolated P5 register-only upgrade returned helper 2.1.0 and removed its own files on uninstall.

## Reproduction

Use the pinned dependencies from `tests/p0/package-lock.json` and `tools/monaco/package-lock.json`. Run from the repository root on Windows. Set `CBOJ_TEST_PYTHON` to the installed Python interpreter. The Chrome verification helper registers a private host name for its disposable profiles. The installer test redirects its registry and installation roots, exercises the production host name and restores its private environment on exit.

```powershell
npm.cmd --prefix tests/p0 ci
npm.cmd --prefix tools/monaco ci
npm.cmd --prefix tools/monaco run build
foreach ($suite in 'p0','p1','p2','p3','p4','polish','legacy','p5','ime','performance') {
    & ./tests/p0/p41-verify.ps1 -Suite $suite
    if ($LASTEXITCODE) { exit $LASTEXITCODE }
}
& $env:CBOJ_TEST_PYTHON -X utf8 -B -m unittest discover -v -s tests/p0 -p 'native*test.py'
& ./tests/p0/p5-install.ps1 -Python $env:CBOJ_TEST_PYTHON
foreach ($ref in 'f5fd0b4','cfb8499','22192f2') { node tests/p0/upgrade.mjs $ref }
node tests/p0/p41-upgrade.mjs
python tools/package.py --ref HEAD --output dist
node tests/p0/p5-packages.mjs dist
```

For a manual check, load the direct ZIP's extracted folder in Chrome and rerun `host/install.ps1 -RegisterOnly -ChromeOnly` with the installed Python and JDK. In a problem workspace select Java, start the timer, run the published samples locally, close and reopen the panel, and check the restored draft and clock. Authenticated production submission, judging and external Git integration remain owner-initiated checks during ordinary problem solving. All automated form, polling and judge-lifecycle checks in P5 used local fixtures. No program or input was posted to live BOJ or Wandbox during verification.
