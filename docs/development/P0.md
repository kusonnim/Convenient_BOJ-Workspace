# P0 baseline and regression harness

**Review gate · 2026-11-25.** Convenient BOJ 1.3.3 loaded unpacked in the installed Windows Chrome. The split opened on the public A+B problem. Local fixtures exercised the manual submission flow in both Chrome script worlds. The checked-out Python host compiled and ran C and C++ with the installed GCC toolchain. Opening a second submission closed the first tab. Disconnecting an active native job stopped its child but left a temporary directory.

## Reproduce

Run these commands from the repository root with Node 20 or newer, npm, installed Google Chrome with the DevTools `Extensions.loadUnpacked` command, and Python 3. The native suite reports skips if the host cannot discover GCC or G++. `CBOJ_CHROME` optionally selects a full Chrome executable path. The browser profiles and native test inputs are disposable.

```powershell
npm.cmd ci --prefix tests/p0 --ignore-scripts --no-audit --no-fund
npm.cmd --prefix tests/p0 test
py -3 tests/p0/native_test.py
```

The browser suite stages the eight release inputs under its ignored output directory. It uses the original manifest, fixed extension key, content scripts, service worker and vendored editor. Chrome handles storage, tab focus, runtime messaging and port delivery. Playwright fulfills problem, submit and status URLs from local HTML. DNS and proxy access are disabled in these profiles. The doubles supply native-port replies and Wandbox responses. The native suite independently starts the actual host and exchanges binary-framed messages over its pipes.

The optional live check below opens only the public problem in a fresh profile, permits GET requests for its assets, probes native host registration with `info`, and captures the closed and open split. The default test command is offline after dependency installation.

```powershell
node tests/p0/live-smoke.mjs
```

The workspace owns the CodeMirror instance, MIME mode, custom themes, keymap, cursor, undo clearing, selection handling, refresh and resizing. The first `$0` in a new template selects the insertion point. Leading groups of four spaces convert to tabs in tab mode. The default C++ template uses `bits/stdc++.h` and fast I/O. |

The final click and any CAPTCHA belong to the user. A failed fill attempts clipboard fallback. |
| [Status watcher](../../content/status.js) and [row parser](../../shared/boj.js) | The managed status tab returns focus to its opener, initially selects the first row linking to the problem, then follows the solution ID. Eligibility of that first row does not include a username check. |
| [Native host](../../host/cboj_host.py) and [installer](../../host/install.ps1) | A Python process handles each native connection. The installer copies a launcher, script and stdio manifest into a per-user directory and registers the fixed origin in HKCU for Chrome, Edge and Whale. Optional winget paths can install Python or WinLibs. The uninstaller removes the runner files and registration. |

**Keyboard and editor state.** Alt+C toggles at document level, including outside the editor. In CodeMirror, Ctrl+S saves, Ctrl+Enter runs all extracted samples, and Ctrl+Shift+Enter opens the submit tab. Command-key aliases exist for the editor actions. Tab, Shift+Tab, Enter and Backspace have custom indentation rules. In a running terminal, Enter sends a line, Shift+Enter permits a newline, Ctrl+D sends any remaining text and EOF, and Ctrl+C stops when there is no text selection. Terminal Enter checks composition. The global toggle has no composition guard. Drafts store a cursor. Scroll, selection, undo history and the active lower tab have no persistent entries.

**Sample comparison.** Each `pre#sample-input-N` supplies raw text and pairs with `#sample-output-N`. Comparison removes carriage returns, trims spaces and tabs from line ends and drops trailing empty lines. Internal whitespace and leading indentation count. Only stdout participates. Missing expected output is run-only, while an existing empty output element is judged. A special-judge label marks a matching sample as advisory.

**Submission messages.** The workspace sends `cboj:open-submit`. Submit and status scripts ask `cboj:is-submit-window`. Entering the managed status page sends `cboj:submitted` to restore focus. The parser recognizes `ac/pac/wa/pe/tle/mle/ole/rte/ce` and sends `cboj:judge-done` through the status script on a final result. The worker clears the session and schedules tab closure after 1.2 s.

## Execution contract

The content script uses `chrome.runtime.connect({name:"cboj-runner"})`. The worker lazily opens `com.convenient_boj.runner`, forwards messages in both directions and disconnects its native port when the tab port closes. A missing host produces `nohost`. Native stdio frames contain a four-byte native-endian unsigned payload length followed by UTF-8 JSON. The baseline host advertises 1.0.0.

| Request | Replies and behavior |
| --- | --- |
| `info` | `info {version,python,gcc,gpp}`. Compiler values are version strings or null. The UI checks presence for the current family and has a four-second discovery timeout. It does not negotiate protocol capabilities. |
| `batch {id,lang,code,inputs,timeLimit}` | One compile in a fresh `cboj_*` directory, then a separate process per input. `batch-result` echoes the ID and returns `cmd,warnings,results[]` or `error:{code,message}` with empty results. Each result carries stdout, stderr, exit code, elapsed ms and a note or timeout flag. The compile timeout is 60 s and the default per-input timeout is 10 s. |
| `run {id,lang,code,stdin,interactive}` | One current interactive job per host. It sends `compile`, `compiled`, `start`, zero or more `out {stream,data}`, then `exit`. Compile failure emits `compiled {ok:false}` and `exit {compileFailed:true}`. Execution exceptions can emit `error`. Exit can carry `code,ms,killed,overLimit,note`. |
| `stdin {id,data}`, `eof {id}`, `kill {id}` | Apply to the matching interactive job. EOF closes the input pipe. Stop kills its direct child. The batch worker has no corresponding cancel path. |

Local C/C++ uses GCC/G++ even for a BOJ language labeled Clang. The argument list includes `-O2`, the selected standard, `-DONLINE_JUDGE`, `-DBOJ`, `-lm` for C and `-static` on Windows. Interactive C/C++ adds a separate GNU constructor to disable C stdout buffering. Python/PyPy choices both run the host interpreter with `-u`. Interactive output is limited to 2,000,000 bytes per stream. Batch output is captured first and then sliced to 200,000 characters per stream per input. There is no cross-batch compilation cache or interactive wall-clock limit.

When no host or relevant local compiler is available, `cboj:run` sends source and stdin to Wandbox with `save:false`. The worker chooses a compiler from its list/cache or built-in identifiers. The first input runs before the remaining requests are sent in parallel. The baseline offers no separate consent prompt at this fallback. A lost in-flight native job is surfaced as a local failure. The P0 browser runs used synthetic programs and intercepted all Wandbox responses.

## Priorities and proposed phase boundaries

1. **High · P1 execution and lifecycle.** Put compiler discovery, effective environment, argument construction and artifact identity behind a host toolchain interface. The installed x64 compiler needs the matching VC/SDK environment. GNU flags, the unbuffering constructor and the built-in C++ header need independent handling. Keep the BOJ language ID and stored draft separate from the local compiler. Version the capability handshake with a legacy `info` path. Bound input/output before allocation, correlate jobs to their port, and join cleanup on disconnect. Track batch processes and child trees. Gate remote fallback on an informed choice. [Microsoft command-line build environment](https://learn.microsoft.com/en-us/cpp/build/building-on-the-command-line?view=msvc-170)
2. **High · submission ownership.** The singleton session demonstrably loses the first workflow. Track sessions by originating and managed tab plus token, with scoped pending payloads, watches and cleanup. Preserve manual confirmation, focus return and the old storage contract during migration. Keep the isolation regression visible until its later implementation gate.
3. **High · P2 Monaco and MV3.** Introduce an editor adapter for text, mode, position, focus, theme, changes, keyboard handling, sizing and disposal before replacing CodeMirror. Translate zero-based stored positions at that boundary. Package pinned Monaco ESM assets, CSS and workers under a shipped root. Evaluate an extension-origin editor frame with a packaged worker created through `MonacoEnvironment.getWorker`. Expose only the required entry resources to BOJ and scope the frame bridge by origin, source and message schema. An in-content editor with packaged worker URLs is a second candidate requiring proof of worker-origin and CSP behavior in installed Chrome. The current release has no Monaco workers or web-accessible resources. [Monaco ESM integration](https://github.com/microsoft/monaco-editor/blob/main/docs/integrate-esm.md) · [Chrome extension CSP](https://developer.chrome.com/docs/extensions/reference/manifest/content-security-policy) · [Web-accessible resources](https://developer.chrome.com/docs/extensions/reference/manifest/web-accessible-resources)
4. **High · P3 clangd.** Add a constrained native LSP transport with its own process lifecycle, byte-counted `Content-Length` framing, request IDs, cancellation, UTF-16 offsets and per-tab document versions. Build compile commands from the actual x64 VC/SDK environment using clang-cl-compatible flags. clangd's query-driver extraction expects a GCC-compatible probe. Verify STL/header resolution and stale-response rejection with the real analyzer before enabling providers. Keep compiler diagnostics distinguishable from analysis diagnostics. [clangd compile commands](https://clangd.llvm.org/design/compile-commands) · [clangd configuration](https://clangd.llvm.org/config) · [LSP specification](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)
5. **Release gate.** Preserve the extension ID and upstream attribution. Obtain verified redistribution rights before publishing a derivative. Include future editor assets and their notices in the release allowlist.
