# P4.2 · Final workspace integration

## What is included

This build combines the Windows workspace and editor-polish branches in the owner’s official fork of gaudium1257’s Convenient BOJ. The original split view, drafts, templates, submission form and judge view come from upstream. P4 incorporated the v1.4.0 sample reader, per-problem test format, line comparison and bounded Wandbox execution. The derivative adds x64 MSVC, Monaco, local clangd analysis, execution cleanup and the workspace features below. The owner confirmed permission from the original author. The inspected upstream tree has no root license. Bundled components retain their individual notices. [Upstream v1.4.0](https://github.com/gaudium1257/Convenient_BOJ/tree/v1.4.0) · [Fork](https://github.com/kusonnim/Convenient_BOJ-Workspace)

| Area | Integrated behavior |
| --- | --- |
| Cases and execution | Samples and user cases share one view. Custom tabs support naming, drag and keyboard reordering, inclusion in batches and selected execution. The native runner preserves order across groups of up to 64 inputs and 512 KiB. Each input uses the configured per-test timeout. Expected empty output is distinguishable from a run-only case. A mismatch shows the first differing line and preserves the raw streams. The interactive terminal has its own time limit. |
| Editing | One Monaco model owns the active draft. Local C++, C and Python snippets support tab stops. The C++ provider combines snippets and clangd suggestions. Eight palettes cover the panel, Monaco and completion widget. Wrap, type size, line height, Sticky Scroll, bracket guides, symbol occurrences and Breadcrumbs are configurable. Formatting C or C++ is an explicit local, undoable action. |
| Power Mode | Off by default. Spark, Aurora and Pixel share a bounded canvas. Combos, intensity and optional shake work during typing. Reduced motion suppresses the animation, and disabling or closing the editor disposes the contribution. |
| Navigation | The Problems panel jumps using Monaco UTF-16 positions. Terminal links retain the compiled file, document generation, revision and compiler column units. They account for tabs and multibyte characters, and report a stale location if the draft changed. |
| Data and submission | The popup exports a local plaintext backup and can keep or explicitly replace conflicting values. It merges case IDs, snippet languages/IDs/prefixes and template languages. It keeps unrelated records and protects open drafts. Form ownership, pending code and judge records remain per-tab and excluded from backup. Only the owner initiates final submission on the official page. |

### Reproduce

From the repository root, install the locked test dependencies using `npm.cmd --prefix tests/p0 ci`. The build commands are `npm.cmd --prefix tools/monaco ci` and `npm.cmd --prefix tools/monaco run build`. The following commands use the project’s private registration and shared lock for version-sensitive browser checks. The verification recorded here also ran the same Playwright configurations with the production-name, register-only installation.

```powershell
$env:CBOJ_TEST_PYTHON = (Get-Command python -CommandType Application).Source
foreach ($suite in 'p0','p1','p2','p3','p4','polish','legacy','ime') {
    & ./tests/p0/p41-verify.ps1 -Suite $suite
    if ($LASTEXITCODE) { exit $LASTEXITCODE }
}
foreach ($suite in 'native_test.py','native_p1_test.py','native_p3_test.py','native_polish_test.py') {
    & $env:CBOJ_TEST_PYTHON -B (Join-Path tests/p0 $suite)
    if ($LASTEXITCODE) { exit $LASTEXITCODE }
}
```

The persistent-profile checks are `node tests/p0/upgrade.mjs` and `node tests/p0/p41-upgrade.mjs`. The real-server startup workload is `node tests/p0/editor-performance.mjs p42`. When another worktree is active, run these latter commands under the same exclusive system-resource lock. Keep the previous install and baseline evidence separate from generated test output.

## Installation and manual review

1. Extract the fork’s main ZIP to a lasting folder, or clone the fork. Open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select the folder containing `manifest.json`. The published source includes Monaco, its worker, the palettes and their notices. [Main ZIP](https://github.com/kusonnim/Convenient_BOJ-Workspace/archive/refs/heads/main.zip) · [Installation guide](../../README.md#installation)
2. For local execution, run `host\install.bat` on Windows. With Python and the Windows toolchains already installed, use `powershell -ExecutionPolicy Bypass -File host/install.ps1 -RegisterOnly -ChromeOnly` from the extension root. MSVC requires the x64 C++ tools and Windows SDK. C++ analysis needs local clangd and compatible headers. Formatting needs local clang-format. Reload the extension and problem tab after upgrading. The fixed Chrome extension ID is `mabfdombglhmfnjklbnoglebinejifdi`.
3. On a local problem fixture open the panel with Alt+C. Add a custom case, run it, reorder it and reopen the problem. In the popup choose a theme and a snippet. In a C++ draft, open completion with Ctrl+Space, inspect a breadcrumb, scroll into a nested function, then format with Shift+Alt+F and undo. Power Mode can be enabled for a typing demonstration and disabled in the popup.
4. Back up drafts before moving an installation. For rollback, keep the same profile, extension ID and unpacked location, restore the previous source files, rerun that version’s installer and reload the problem tabs. The owner’s existing files and uninstaller protections are covered by the upgrade/cleanup fixtures. [P4 installation and recovery details](P4.md)

## Scope and limitations

All submission, judging, polling and tab-lifecycle checks used local fixtures. Authenticated BOJ submission, CAPTCHA and the owner’s external submission-to-Git integration remain reserved for normal owner-initiated use. Wandbox requests and responses were exercised with local doubles. Absolute timings depend on the installed tools, machine and draft. Verification covers the recorded Windows Chrome installation. Other operating systems, Edge and Whale were outside this run. Upstream’s Java runner, stopwatch and Web Store distribution remain available from the original project. This derivative’s verified execution languages are C, C++ and Python. [Upstream audit](P4.md#starting-point-and-integration-audit)
